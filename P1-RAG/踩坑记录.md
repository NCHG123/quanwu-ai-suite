# 全屋定制出海 AI 项目 — 踩坑记录

> 用途：复盘 + 面试素材（JD 里「RAG 实操、踩过坑并解决过」的直接证据）
> 每条格式：现象 → 原因 → 修法 → 状态

## 一、环境类

### 1. 双 Python 环境冲突
- 现象：机器上两个 Python（3.13.15 系统版 / 3.12.14 uv 管理版），分不清用哪个
- 原因：uv 包管理工具自动下载了一个备用解释器
- 修法：`uv python uninstall 3.12.14`（uv 的 Python 没有卸载程序，只是文件夹，别手动删）
- 状态：✅ 已修

### 2. onnxruntime DLL 加载失败
- 现象：`ImportError: DLL load failed ... 动态链接库(DLL)初始化例程失败`
- 原因：VC++ 运行库太旧（2019 版 14.23），onnxruntime（2026 版）需要更新的运行时
- 修法：装微软官方 VC++ 2022 Redistributable（`aka.ms/vs/17/release/vc_redist.x64.exe`）
- 状态：✅ 已修

### 3. HuggingFace 模型下载失败（国内网络）
- 现象：下载报 `401 Unauthorized`（Xet 相关）或直接卡死
- 原因：① 新版 huggingface_hub 默认走 Xet 存储，国内不通；② 国内直连 huggingface.co 慢
- 修法：① `HF_HUB_DISABLE_XET=1` 禁用 Xet；② `HF_ENDPOINT=https://hf-mirror.com` 走国内镜像
- 状态：✅ 已修

## 二、模型 / 检索类

### 4. 嵌入模型语言不匹配
- 现象：用纯中文模型 `bge-small-zh-v1.5` 处理英文素材，检索效果差
- 原因：素材是英文（面向海外 B 端准备），模型是中文优化
- 修法：换多语言模型 `paraphrase-multilingual-MiniLM-L12-v2`
- 状态：✅ 已修

### 5. 跨语言检索弱
- 现象：中文问题问英文资料，相似度分数低、排名不稳（中文「起订量」匹配不到英文「MOQ」）
- 原因：跨语言检索比同语言难，模型要多做一步「翻译」
- 修法：查询翻译前置——`translate_query_if_cn` 用 DeepSeek 把中文 query 翻成英文再检索（轻量不换模型）
- 状态：✅ 已修（项目3 评测驱动，R4 转 pass）

### 6. 固定字符切块切碎句子
- 现象：40 字符切块，英文约等于 7 个单词，句子被拦腰砍断（`ard your first bulk order. Q: Do you ac`）
- 原因：按固定字符数硬切，不认句子/行边界
- 修法：改为按「行」切块 + 400 字符
- 状态：✅ 已修

### 7. 表格 / 结构化内容检索命中率低（最经典的 RAG 坑）
- 现象：中文问「折扣阶梯」「成本构成」，检索不到英文表格里的 -2%~-5% 阶梯
- 原因：空行切块 + `min_len=50` 把「Volume Discount Ladder」这类标题扔了，表格块失去语境标签，向量对不上
- 修法：带章节标题切块（正文块文本 = `[标题] 正文`）+ `TOP_K` 3→5
- 状态：✅ 已修

## 三、安全 / 权限类

### 8. 内部资料泄露给对外入口
- 现象：对外客服入口能搜到 internal 文档（含折扣底价、成本构成）
- 原因：知识库混着 internal 文档，检索时不做区分
- 修法：权限过滤——给每块打 audience 标签（文件名含 internal 判内部）+ `search()` 加 clearance 参数
- 状态：✅ 已修（验收：对外问折扣答不出 -2%~-8%，对内能答出）

### 9. 文件名判断 internal 太粗
- 现象：`14-communication-guidelines.md` 文件名没有 "internal"，但内容是 INTERNAL-ONLY，漏进对外检索
- 原因：只按文件名判断权限，不按内容
- 修法：`_audience` 升级为「文件名含 internal **或** 内容含 INTERNAL-ONLY / AUDIENCE LEVEL: INTERNAL 标记」判内部
- 状态：✅ 已修（你亲手测试复现的，很有价值）

## 四、工程 / 流程类

### 10. 执行者自作主张偏离规格
- 现象：执行时用自己的判断反复改 WorkBuddy 方案（fastembed 换 sentence_transformers、改切块方式），导致来回返工、用户干着急
- 教训：有既定规格时**原样执行**，有技术顾虑最多提一句，不擅自替换
- 状态：✅ 已改（教训记入工作方式）

### 11. 目录结构多建一层
- 现象：多建了 `01-rag\` 子文件夹，和规格要求的扁平结构（docs/.env 直接在项目根）对不上
- 原因：执行时自作主张加层级
- 修法：清理归位（docs/.env 移到项目根，删掉多余层级）
- 状态：✅ 已修

### 12. 跑错文件
- 现象：测权限过滤时跑了旧的 `rag.py`（无过滤），而不是 `entry_external.py`
- 原因：文件名相似、没看终端提示语
- 修法：跑之前先看终端第一行（每个入口打印不同标题）；执行清理步骤删旧文件
- 状态：✅ 已修

### 13. 交互脚本测试时 input() 输入跑到 PowerShell
- 现象：问题被 PowerShell 当成命令（`无法将"xxx"识别为 cmdlet`）
- 原因：在 PowerShell 提示符直接打字，而不是在 Python 等输入时打
- 修法：先运行脚本，等出现「请输入问题：」再打字
- 状态：✅ 已修

### 14. 复制粘贴代码混入隐藏字符
- 现象：代码里 `__main__` 混进了零宽字符，`if __name__ == "__main__"` 不生效
- 原因：网页/聊天复制粘贴的产物
- 修法：手写或仔细检查不可见字符
- 状态：✅ 已修

---

### 15. 回复语言没按入口区分
- 现象：对外入口（海外客户）问英文问题，却返回中文答案
- 原因：llm.py 的 prompt 是中文、且没指定回复语言；语言策略没做成「按入口区分」（对外英文、对内中文）
- 修法：`answer()` 加 `lang` 参数（默认 en），prompt 加「用{语言}回答」规则，各入口传对应语言（对外/api=en、对内=zh）
- 状态：✅ 已修（语言从 bug 变成设计点——「调用上下文注入」）

### 16. 组合问题稀释检索（一问多题 → 单个答不准）
- 现象：销售Agent对 quote 意图一次问「MOQ+交期+认证+付款」4个问题，结果 MOQ/付款被"打太极"，只有交期/认证答得全
- 原因：RAG 检索对组合问题会稀释——一次问太多，检索结果分散，单个维度（MOQ）反而没突出
- 修法：research_question 的 quote 分支改成聚焦单问（"What is your exact MOQ for a trial order, and what is the standard container load (40HQ)?"）
- 状态：✅ 已修（项目3 评测驱动，S1 转 pass）
